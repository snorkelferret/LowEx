Workspace figures count only what a developer is staging: the game store is shared and belongs to nobody, and pulling an approved asset back to work on it uses none of their allowance. So the two totals differ, and they should — nothing here is billed to anyone.

Storage by game version not built

Not built yet, and it cannot be until there is a game version to measure. Nothing in the system currently records which content belongs to one.

When there is, this will show the total size of each version — production, development, experimental, and any others — so the figure needed to host a build elsewhere can be read off rather than estimated, and so a version that is growing out of proportion to the others is visible before it becomes a problem. The follow-on is a view of where the bytes actually went inside a version, for deciding what is worth optimising. Neither is being built now.

One thing that will be true when it is: content is stored once and referenced by everything that needs it, so the same file counted under two versions is one file on disk. Per-version figures will not add up to the total above, and that is the design rather than an error in the arithmetic.
